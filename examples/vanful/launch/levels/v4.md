# v4: make the playtest produce evidence (toward Fundable)

**User's step:** "Playtest-ready". A dedicated free Supabase project `vanful` holds anonymous play events,
in-game feedback and the waitlist, with a private results report for the owner.
**Headline:** *every playtest session becomes data you can show.*

| # | track | item | acceptance check |
| --- | --- | --- | --- |
| 1 | Product | Schema `0002_playtest.sql`: `play_events`, `feedback`, hardened `waitlist`; anon may **insert only listed columns**, with size limits; no reads | DB test: anon inserts succeed; anon select/update/delete fail; oversized or unknown events rejected |
| 2 | Product | Telemetry: anonymous device + session ids, batched inserts, flush on page hide, no PII | e2e: playing the tutorial posts `tutorial_start…tutorial_done` with device/session ids and no email or IP field |
| 3 | Trust | Consent: on by default with a clear notice; **off** if Do-Not-Track or Global Privacy Control is set; toggle in About | e2e: toggling off stops all posts; About text matches behaviour |
| 4 | Product | Feedback card after the first finished shift: door rule (yes / sort of / no), fun 1–5, play tomorrow's Daily (yes / maybe / no), optional comment ≤ 500 | e2e: submit posts one row; card doesn't reappear; Enter doesn't leak to the game |
| 5 | Pitch | `pitch/metrics.md`: 5 playtest metrics, exact SQL definitions, targets set *before* results | each metric maps to an event or feedback field |
| 6 | Pitch | Owner report: `supabase/queries/playtest_report.sql` + `npm run report` (service key stays local) | report runs on the test DB and prints all 5 metrics |

**Not in this level:** pitch deck and one-pager (they wait for real numbers), paid analytics, accounts.
**Blocked on you:** the live project (free-tier limit of 2 active projects).

is until the playtest runs on the live project.
